# V2.7 — Unified JSON / Excel Validation

Upload either TruckX JSON or the supported FMCSA PDF-converted XLSX. Both inputs are normalized into the same event schema and passed to **the exact same** `validate_single_driver_locations.audit` function. All checks, settings, filters, map and results are shared.

Excel is an input adapter, not a second validation engine. `INT` entries are preserved for review but are not status transitions. Embedded images are counted and flagged; text contained only in images is not interpreted. PDF-style approximate location strings are compared using the same normalization rules as JSON: mismatches can therefore require manual geographic verification, not automatic FMCSA violation conclusions.

Install with `pip install -r requirements.txt`, then `streamlit run app.py`.

# TruckX Single-Driver Location Validator V2

A local Streamlit application for checking **custom single-driver status/location transition rules**. It is **not** a complete FMCSA HOS compliance audit.

## Installation (Ubuntu / Python 3.10+)

```bash
cd truckx_streamlit_app
python3 -m pip install -r requirements.txt
streamlit run app.py
```

Upload the original TruckX bulk-details JSON in the app, or place a `.json` file inside the optional `data/` directory and select it.

## Default settings

- **GPS Matching OFF**: written location text only; coordinates are not consulted.
- **Exclude ZIP Code ON**: remove trailing US ZIP or ZIP+4 before comparison.
- Location text normalization: case-insensitive, extra whitespace and minor punctuation ignored.
- GPS ON uses a 100m pass tolerance and 500m nearby review radius (both adjustable). These are project heuristics, not regulatory standards.

## Checked transitions

1. `OFF_DUTY` or `SLEEPER_BERTH` → `ON_DUTY` or `DRIVING`: same location.
2. `ON_DUTY` → `DRIVING`: same location.

Only immediately adjacent, chronologically ordered real events are checked. Events are deduplicated by event ID. The audit continues across midnight whether or not the export repeats the prior day's last event. If an entire calendar day is missing, checks that span the gap are marked `DATA_GAP`. Placeholder `0000-00-00` timestamps are never interpreted as real dates. Separate carry-forward checks are reported where the data permits.

## Dashboard

- Overview with daily summary and chart
- Problems and detailed side-by-side inspection
- All checked transitions
- Data-quality diagnostics
- Date range, problem-only toggle, and search
- Optional filtered CSV download

## Command line

```bash
python3 validate_single_driver_locations.py /path/to/export.json
python3 validate_single_driver_locations.py /path/to/export.json --gps-matching --tolerance-meters 100
python3 validate_single_driver_locations.py /path/to/export.json --include-zip
python3 validate_single_driver_locations.py /path/to/export.json --output findings.json
```

No report file is generated by default.

## Location overview map (V2.1)

The 📍 Location overview tab displays event pairs on an interactive map. Choose one transition or all filtered transitions. Toggle **Show connection lines (nodes)**, **Show direction arrows**, and **Show START / NEXT labels** independently (arrows require lines). Hover markers and lines for context. The map shows straight connections between recorded event positions, **not a verified driven route**. GPS coordinates are used for map display even when GPS Matching is OFF; location validation still uses written locations only in that mode. An internet connection may be required to display the background map tiles.

## V2.4 — Extended driver, shipment, and ELD/HOS metadata

The **Driver & shipment** tab now provides daily shipping registers, all ELD event fields, source-supplied HOS values/flags, DVIR and trip inspections, unidentified-driver events, and a per-day raw metadata inspector. ## V2.5: PDF-converted Excel input

Choose **FMCSA PDF-converted Excel** at the top of the dashboard and upload the `.xlsx` file. The original JSON mode is preserved. The parser reads XLSX XML cells using Python's standard library (no Excel/LibreOffice required), extracts daily headers and ELD events, converts Excel date serials, handles midnight rollover in reverse chronological event tables, and retains `INT` intermediate positions without treating them as duty-status changes. It also displays driver, license, carrier, USDOT, shipping ID, vehicle, ELD diagnostics, annotations and downloadable CSV/JSON tables.

**Limits:** This reader targets the layout in the supplied workbook. Embedded images are detected and explicitly excluded; it does not perform OCR or reconstruct image-only duty charts. PDF-to-Excel conversion may lose fields or shift columns. Written locations such as `1.8mi E Guasti CA` are approximate; mismatches are marked for review, not as confirmed violations. No FMCSA certification or comprehensive compliance determination is made. Cross-driver/team validation is not yet implemented. Always verify material findings against the original PDF.


## V2.6 — Driver identity and dated shipments

## V3.0: FMCSA Excel distance/bearing normalization
Only the Excel input enables `excel_approximate=True` in the shared audit engine.
The original JSON comparison remains unchanged. For e.g. `0.3mi NNE Castaic CA`
and `0.1mi NE Castaic CA`, compare two displacement vectors from the same
reference place. Estimated difference <= 0.5 miles is PASS; > 0.5 miles is
REVIEW_APPROXIMATE_LOCATION. Different named places are still mismatches.
This is an approximate text comparison, **not** geographic proof or an FMCSA
compliance determination. Embedded images are counted but not OCRed.
